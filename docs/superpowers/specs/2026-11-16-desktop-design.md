## 1. 已确认目标与产品边界

交付 Windows 10/11 x64 桌面应用：离线安装，内置 Python，普通用户无需安装 Python、Node.js 或 npm，也无需终端启动。Windows 最低构建号与所选 Electron 版本的兼容性在基础验证阶段锁定，并写进安装说明。

引擎、ThirdPart 依赖和真实业务数据仍是外部资源。应用提供自动发现、原生目录/文件选择、粘贴路径和重新定位，不依赖当前作者的盘符、用户名或引擎项目名称。

首版以现有 Web 的功能等价迁移为交付底线，同时完善桌面原生操作、引导与视觉体验。已有 exe 满足条件时可复用；只有编译操作要求安装适配的 VS/Build Tools、CMake 和 Ninja。内置 Python 不意味着把 C++ 工具链或引擎许可打入安装包。

首版保持当前单任务受管执行模型。多任务排队、并行计算、远程调度、账号云同步、自动更新、DEM 绘图引擎和与 AntennaDraw 的业务集成列为后续独立需求。它们不影响本次 Web 功能完整迁移；首版可直接打开计算结果和日志目录。

## 2. 调研结论与方案选择

现有 Web 前端为原生 HTML/CSS/JavaScript，后端为 Python 标准库；已有 43 个 Python 自动化测试文件、29 个 JavaScript 自动化测试文件，另有可选隔离浏览器验收脚本和前端测试辅助文件。数量来自文件清点，不代表本轮执行通过。

参考桌面项目实际使用 Electron 45.1.0、electron-builder 26.18.0、Vue 3、Vite、Element Plus，后端为 Node/Express。可以借鉴窗口、目录选择、主进程/预加载边界、用户数据隔离、首次引导、退出保护与 NSIS 打包；不能把其 Node utilityProcess 启动方式直接用于 Python。

| 方案 | 收益 | 成本与限制 | 建议 |
| --- | --- | --- | --- |
| Electron + Vue 3 新桌面界面 + 复用 Python 业务层 | 接近参考项目；适合表单、表格、日志和多阶段工作台；业务校验保持一致 | 需要迁移前端交互与状态连接，并增加 Python 托管 | 推荐 |
| Electron + 原有页面改造 | 最快形成可启动桌面包，复用既有页面测试 | 页面结构和全局状态限制较多，长期维护与视觉提升空间较小 | 可作早期技术验证，不作最终界面 |
| Tauri + Vue + Python 边车进程 | 外壳体积有机会更小 | 引入 Rust/WebView2 和另一套分发、进程托管要求，与参考项目复用较少 | 首版不采用 |

推荐技术组合：Electron、Vue 3、TypeScript、Vite、Element Plus、electron-builder/NSIS、Python 3.13 x64 嵌入式运行时。版本在基础验证时固定进 lock 文件，并检查 Windows 支持范围、依赖兼容性及安全维护状态；参考项目版本作为依据，不盲目整套复制。状态按工作流、编辑器、会话、设置分域管理，避免一个大 store 统管全部业务。

## 3. 架构与代码边界

```text
Electron 主进程
├─ 单实例、窗口、原生对话框、文件定位、日志另存为、退出控制
├─ preload：只公开明确的桌面操作，不暴露任意 IPC/命令/文件系统
├─ Python 服务监管入口：生命周期通道、启动就绪、退出与异常监管
│  └─ Python 本地服务：随机回环端口、鉴权、业务 API
│     ├─ 原有项目配置、装配、文件编辑、预检、结果验证
│     └─ 原有 ManagedProcess / RuntimeGuard / ResourceLease / RunHistory
│        └─ 外部 C++ 引擎、编译工具及其子进程
└─ Vue 桌面工作台：通过本地 API 调用业务，通过 preload 调用原生操作
```

- Python 保留领域逻辑，Electron 不重复实现 XML/CSV 变更、结果判断和资源锁。
- Web 原有入口继续可用；新增桌面入口加载构建后的 Vue 静态文件，不让桌面发布依赖 Vite 开发服务。
- 优先直接沿用 `workflow-state.js` 的纯逻辑，增加类型与适配层；不要直接把依赖全局 DOM 的 `project-build.js`、`editors.js`、`runtime-session.js` 塞进 Vue。将它们的业务契约和竞争条件测试迁移为视图无关控制器与组合函数。
- 工作流草稿、已装配快照、预检版本、编辑器草稿和已运行 sid 分开建模。后端是文件、占用及执行状态的事实来源。
- 桌面服务只监听 `127.0.0.1`，由系统分配空闲端口；就绪握手回传真实端口，规避 Chromium 禁用端口。禁止先找空闲端口再单独绑定的竞争模式，也不按端口杀陌生进程。
- 启动凭证通过生命周期管道传递；使用独立 Electron session、每次启动随机凭证、HttpOnly/SameSite cookie、精确 Host/Origin 检查与 CSP。不将凭证放在 URL、命令行、日志或诊断包中。
- 窗口关闭 Node 集成，启用上下文隔离和沙箱；主进程校验 IPC 调用窗口、主 frame、参数及来源；禁止外部导航、任意弹窗和 webview。打开文件夹不透传任意 shell 命令。

## 4. 引擎与业务资源自动发现

### 4.1 用户路径

首次引导：添加引擎项目 → 检测构建和资源 → 选择地图/工参/输出目录 → 核对配置 → 进入工作台。可跳过配置先浏览帮助、设置和历史，但运行入口明确显示缺少什么。

各路径字段提供“选择…”“扫描此目录”“重新检测”“打开目录”，保留手动输入。扫描结果显示路径、类型、识别依据、可用状态、缺少项；检测候选和已保存配置分开，确认后才保存。

### 4.2 扫描范围与体验

1. 快速检测只检查已保存路径、用户本次选定目录及所选引擎的关联目录；工具链继续优先使用 VS 注册信息、`vswhere` 与实际文件检查。
2. 扩大搜索由用户选择父目录或磁盘，执行前展示范围。默认有限深度和文件数预算，可取消并返回部分结果；深入搜索由用户明确启用。
3. 后台按目录批次处理并限流，展示已检查目录数、发现数、当前范围和跳过原因；不伪造剩余时间或百分比。
4. 默认跳过系统目录、回收站、无权限目录、网络共享和重解析点；显式选定共享路径时单独检测可达性，不递归追踪链接。扫描不执行发现的 exe、脚本或 CMake，不改系统 PATH。
5. 多个项目、多个 XML、多个配置源或 exe 候选都展示列表，不按“最新时间”或“第一个目录”静默决定。
6. 扫描有 session/id 与取消代次；离开页面、取消或更换范围后，旧结果不能覆盖新选择。

### 4.3 内容识别与换电脑

| 资源 | 识别方法 | 失败时操作 |
| --- | --- | --- |
| 引擎源码项目 | 复用 `CMakeLists.txt`、`LiShuttle/`、`SwanUtility/incl/LiShuttleTypes.h` 等内容校验，不限定目录名 | 显示缺失项并重新选目录；首版不假设任意 exe 文件夹等价完整引擎项目 |
| 构建/程序 | 读取项目实际 CMakePresets、构建目录和产物，核对 Debug/Release、exe 与 DLL 候选 | 可选择匹配已有构建；只有需要编译时检查工具链 |
| 配置及依赖 | 所选项目的 CONFIG_SRC、DLL_SRC、runtimelibrary 样例和实际资源 | 展示候选与来源，允许显式引用项目外资源 |
| 地图 | 复用 `.das` 室内优先与室外 `heights/index.txt` 的现有规则 | 区分“地图根目录”和“具体地图目录”；内容缺失与未知兼容性分别提示 |
| 工参/任务 | 读取 CSV 表头、RuntimeSchema 根节点、区域/天线/模型约定，不靠单一文件名 | 多候选明确选择；提示数据格式与引擎功能是否匹配 |
| 输出与路测 | 输出由用户选择可写目录；路测依当前项目/实际配置识别 | 缺失时保留空白并指明配置项，不借用其他项目或作者路径 |

换电脑后导入旧配置，失效路径显示“需要重新定位”。支持为明确选定的旧目录前缀建立本次替换映射，逐项预览与重新校验，不对整盘或未知 XML 文本做全局替换。

XML 操作必须继续区分：原配置直接使用、纯字节副本导入、路径适配副本。纯导入不顺便改路径；需要换路径时进入单独适配预览。原文件保留，输出目录根据 XML 根 `name` 计算，不由 XML 文件名猜测。

## 5. 桌面界面与视觉设计

### 5.1 布局

- 顶部持续显示当前项目与构建、已选 XML、功能、后台状态；正在执行时另外显示锁定的运行上下文，避免与当前浏览草稿混淆。
- 左侧分为“工作台、运行记录、环境与路径、帮助”。工作台内部保留六阶段导航：项目与环境 → 程序准备 → 任务与输入 → 装配与确认 → 参数与检查 → 运行与结果。
- 中央只展开当前阶段，保持上下文和阶段完成状态；允许返回核对。编辑和运行限制由后端占用与版本状态决定，查看历史不改变执行上下文。
- 底部可拖动日志抽屉，折叠后仍可见任务状态、耗时、错误数和展开按钮；日志暂停跟随不暂停采集，支持查找、回到底部、完整另存为。
- 当前阶段主要动作固定在页脚附近，例如“保存配置”“预览装配”“运行前检查”“开始运行”；禁用旁明确显示原因与前往修复入口。

### 5.2 视觉规范

专业工程工具风格：浅灰工作区、白色内容卡片、深蓝侧栏、蓝色主动作；重点投入信息层次、表格和路径阅读。采用 8px 间距基准、14px 正文、16px 区块标题、适度圆角和轻分隔，使用系统中文字体，目录与日志用等宽字体。状态同时使用图标、文字和颜色，正文对比度至少 4.5:1。

起始窗口目标 1440×900；在工作区允许时最小约 1100×700，小屏自动收拢辅助信息、改为纵向滚动。验收覆盖 1366×768 与 1920×1080 屏幕，以及 100%/125%/150%/200% 缩放；不强制窗口超出实际可用屏幕，不隐藏关键运行按钮。路径支持复制、完整查看、打开定位；横向滚动限于宽表格和日志。

首版以明亮主题完成全套视觉验收。深色主题不作为功能验收依赖，避免只换颜色而遗漏表格、弹窗和日志可读性。

### 5.3 核心页面细节

| 页面 | 主要交互 |
| --- | --- |
| 项目与环境 | 当前项目卡片、来源/缺失项、自动发现候选、原生路径选择；本机工具链与项目资源明确区分 |
| 程序准备 | 已识别 exe 与构建信息、复用已有程序、项目体检、增量编译；编译过程与本次结果分开呈现 |
| 任务与输入 | 三种 XML 入口用清晰选项卡；地图/任务列表可搜索；显示真实目录、格式和候选数 |
| 装配确认 | 来源→目标差异表、资源清单、备份/影响范围、实际输出目录；预览与确认分两步 |
| XML 参数 | 按功能与分组检索；字段含中文说明、原始键、单位、当前值、来源、只读原因；延续现有自动保存语义，明确显示保存中/已保存/失败草稿 |
| CSV 工参 | 冻结表头、虚拟滚动、大表加载状态、单元格编辑、整列修改影响预览；显式保存/放弃，与 XML 自动保存清楚区分 |
| 运行与结果 | 先显示可操作的检查报告，执行时显示真实阶段与耗时，不伪造引擎百分比；结果按进程、产物、业务三层展示 |
| 运行记录 | 按项目/功能/状态筛选、分页、查看固定 sid、日志和归档；同时显示当时结论及当前文件是否仍匹配 |

## 7. 安装资源、用户数据和迁移

安装目录只读存放 Electron、Vue 构建结果、Python 运行时、业务源码、脚本、模板、参数说明与许可。打包资源置于适合 Python 与批处理读取的真实目录，不要求 Python 访问 ASAR 内文件。

默认用户根目录：稳定版 `%LOCALAPPDATA%\LiShuttleWorkflow`，开发版 `%LOCALAPPDATA%\LiShuttleWorkflow-Dev`。包含 `env/` 档案与快照、`jobs/` 生成任务单、`runs/` 会话归档、`maintenance-archives/` 平台配置清理归档、`logs/` 应用日志、`cache/` 扫描缓存及桌面偏好。单实例锁、session 与用户根路径均按渠道隔离。

引擎 Bin、输入、输出仍位于用户明确选择的外部目录；XML/CSV 修改延续备份和版本校验，不把大型地图/结果复制到 AppData。跨 Web、桌面、CLI 的资源锁继续基于规范化外部路径共用，不能随渠道分离而失去互斥。

路径改造覆盖 `core.py` 的 ENV_FILE/PROJECTS_FILE/JOBS_DIR/RunHistory、`ProjectStore` 默认路径、配置快照、渲染子进程、批处理工作目录、静态目录，以及 `server.py` 当前写入 `ROOT/docs/runtime-config-archives` 的清理归档入口。`cleanup_plan` 的相对路径解析需区分资源根、用户任务根和旧 manifest 的来源根，不能因迁移而扩大清理归属。新增显式资源根与用户数据根，旧 Web/CLI 默认行为保持兼容；桌面子进程全部继承同一配置快照与数据根。

Python 运行时使用固定版本、校验下载 SHA-256、配置嵌入式 `_pth` 和 stdlib；构建验证 `ctypes`、编码、XML、HTTP、subprocess 等依赖。所有运行/构建/体检子脚本通过明确的内置解释器调用：新增 `LISHUTTLE_PYTHON` 等统一入口，旧 CLI 无此设置时允许回退系统 Python。不能只让主服务用内置 Python、批处理仍调用 PATH 中的 python。

现有批处理使用 GBK 和延迟变量扩展。必须审计中文、空格、`&`、`!`、`%`、括号及长路径经过的所有 shell 边界；尽量以参数数组直接调用工具，仅在初始化 MSVC 环境时保留受控批处理。无法支持的路径必须在执行前明确拒绝并提供可行路径选择，不得静默截断或执行错误命令。

首次导入 Web 配置由用户选择旧工作流目录。先展示项目、路径状态和数量，备份目标后迁移项目档案、工具链和任务绑定，不修改旧安装。历史归档提供独立导入选项，以来源命名空间保留原 sid/上下文、防止碰撞；缺失历史结果只标记不可用，不当作新结果。真实任务/地图/输出不随配置导出复制。导出的配置含本机路径，界面明确说明其内容。

用户配置带 schema 版本。升级先备份、迁移成功后原子切换，失败保留旧版本和恢复入口；遇到比当前应用更新的数据格式停止写入。手动覆盖升级和卸载默认保留用户数据。清理设置与删除外部业务文件使用不同入口，不能混为卸载动作。

## 8. 生命周期、故障与恢复

- 双击第二次启动聚焦现有窗口；稳定版与 Dev 独立实例，共用外部资源时仍互斥。
- 启动展示可恢复的阶段状态：校验运行时、启动服务、连接工作台。服务必须完成实际就绪握手才加载，超时可查看日志或重试；不反复启动多个服务。
- 采用轻量 Python 服务监管入口，使用现有 Windows ctypes/Job Object 经验托管服务进程树，并用主进程生命周期管道检测断开。保留现有引擎 ManagedProcess 及取消/清理逻辑；Windows 嵌套 Job 和 MSVC 辅助进程行为必须通过故障注入验证，不直接照搬参考项目 C# 监管器。
- 关闭时若有未保存 CSV、待保存参数或配置草稿，显示保存/放弃/返回；正在写入时等待结果确认，不重复提交。
- 正在计算或编译时关闭窗口，提供“继续运行并返回”和“停止任务后退出”。首版不引入托盘后台常驻；用户可最小化窗口保持计算。
- 停止后先等待进程树退出、结果收尾、日志和归档完成，再关闭服务。清理失败显示可核对的进程归属与日志；只终止本应用拥有的进程，不使用按名称或端口的全局结束方式。
- 界面异常可在用户明确操作后重建窗口并读取活跃 sid，不重启引擎；后台崩溃时阻塞写入，显示诊断和重启入口，不自动重跑上次任务。
- 重启将未完成会话标记中断/未确认，展示已保存证据。无法确认进程或文件归属时阻止新的冲突操作，保留恢复记录。

## 9. 必须保持的业务正确性

1. 草稿改变使装配失效；XML/CSV 保存使预检失效；页面切换不改变运行 sid。已装配、已检查和已运行不可合并成一个布尔值。
2. 后端占用为权威：准备、运行、取消、验证、归档全程持锁；跨实例/CLI 使用同一外部资源锁。
3. 请求携带项目/配置修订与文件内容版本；CSV 同时校验格式与来源。过期响应不能写入新项目；冲突不丢草稿。
4. 预览区分普通失败、RUNTIME_BUSY、PREVIEW_STALE、写入结果未知。网络断开不自动重复写；先核对实际文件。
5. 保留原子写入、.bak 和装配回滚。未确认字段只读；不能因为界面统一而补写缺失 XML 字段。
6. 正常退出码、任务结束标记、目录存在或只变化 mtime 均不足以证明成功。保留成功、部分成功、无模型更新、未确认、失败、取消等分级，以及本次产物归属。
7. XML 根 name、任务 ID、实际输出目录与 sid 上下文固定；历史查看或导航不改变日志与结果归属。
8. 主进程退出不代表引擎进程树结束；收尾未完成不提前解锁。后续历史或构建发现失败，也不能重新锁死已完成的操作。

每个阶段以可演示结果与检查证据收口，先完成安装和运行时纵向闭环，再扩展页面。整体设计确认后，逐阶段细化到修改文件、接口、测试用例和小步提交的执行计划。

## 11. 测试与验收计划

### 11.1 沿用的现有检查

```powershell
python -m unittest discover -s tests -p "test_*.py"
node --test (Get-ChildItem tests -Filter "test_*.cjs").FullName
python tests/workflow_browser_check.py
```

浏览器脚本依赖本机已有 Playwright 与 Chrome/Edge；使用临时静态服务和内存 fixture，不触及真实引擎。现有前端测试继续检查原 Web 入口；Vue 组件、适配器和 Electron 另补对应覆盖，不能把旧 DOM 测试通过当成新界面已通过。

重点沿用：workflow_state/integration、project_draft_guards、runtime_configs、safe_editors/editor_integrity/editor_races、assembly_transactions、runtime_config_import、resource_lock、runtime_lifecycle、run_persistence、build_process_release、result_validation、indoor_source_lock、run_history 等现有测试。

### 11.2 新增的必要覆盖

- 发现扫描：假目录树、多候选、中文/空格/特殊符号、权限失败、取消/重新扫描、失效缓存、根与叶目录区分、链接与共享路径边界；扫描期间不执行外部文件。
- 路径/运行时：安装路径只读、用户路径可写；隔离系统 Python/Node 后启动、体检和渲染仍调用内置 Python；命令含空格与元字符不被解释成额外命令。
- 桌面集成：单实例、原生对话框取消、日志另存为、IP/端口来源验证、鉴权失败、CSP、拒绝不可信 IPC/导航。
- 进程生命周期：主窗口关闭、主进程崩溃、服务监管器被结束、Python 服务异常、取消时子进程已脱离原父进程、编译辅助进程、归档失败；均核实归属和资源锁释放顺序。
- 文件安全：外部编辑导致内容版本冲突、同名导入、预览过期、写入响应中断、保存失败保留草稿、装配回滚和历史清理恢复；在安装目录只读时完成清理预览、归档到用户目录，并依据 `restore.json` 核对恢复原路径与原字节（恢复不覆盖用户后来修改的文件）。
- 新 UI：桌面六阶段全链路、三种 XML、室内外与校正、项目切换竞争、历史不覆盖当前 sid、大 CSV/长日志的有界渲染。
- 安装包：缺内置运行时、缺资源、开发 URL、作者绝对路径、真实配置/地图/凭据、版本不一致均应被发布检查拦截；测试和构建工具可从干净 checkout 复现。

真实引擎不放入公共自动化测试。先用隔离假进程/样例检验控制逻辑，再用用户已有、兼容版本的真实项目验证计算；证据表区分真实通过、fixture 通过、未验证。动态发现的所有功能不能因列表可见而被宣称业务验证完成。

### 11.3 量化体验目标

性能数据在固定 Windows 验证机记录版本、CPU/RAM 与样本规模。首次以 10,000 行×30 列 CSV、累计 100,000 行日志、500 条历史记录为样本，采用虚拟化、增量加载及分页；扫描和编辑期间窗口可响应取消与导航。交互反馈目标 200ms 内显示，冷启动目标 10 秒内进入主工作台，超过时显示实际启动阶段。目标不作为未测试即宣称的性能承诺。

视觉检查覆盖空数据、加载、失败、只读、长路径、缩放、键盘焦点与弹窗；至少完整走通室外预测、室内预测与校正代表场景，并核实当前引擎可用的其他功能。

安装包包含完整 Electron、Python 标准库和所需资源，安装后不联网下载依赖。开发机准备依赖和首次打包可能需要联网；后续可通过校验过的构建缓存复现。首版手动覆盖升级，升级和卸载保留用户配置与历史。

构建按白名单收集资源，检查实际打包后的文件树、版本、Python 运行时和测试样例。安装包不包含作者的 `env/`、实际任务单、真实地图、日志、历史、凭据或外部引擎。测试、包检查、发布说明和计划文档需显式纳入版本管理，不沿用参考项目忽略测试的做法；本项目现有 `/docs/` 忽略规则只为桌面方案/发布文档设置窄范围例外。

交付清单：安装包、SHA256SUMS、版本说明、首次配置/路径重新定位指南、功能与外机验收记录、已知限制、第三方许可、可从干净 checkout 运行的构建/测试说明。代码签名有可用证书时接入；未签名时如实标明发布状态，不将本机打包成功等同于外机安装验证。

## 13. 主要风险与控制

| 风险 | 控制与验证 |

| 自动发现误认目录或绑定错误资源 | 内容识别、候选证据、显式确认；检测与保存分离 |
| 多实例/Web/CLI 共用同一 Bin 或输出 | 继续共享操作系统资源锁，跨渠道和跨入口回归 |
| 外部引擎版本、DLL、授权或数据缺失 | 引导明确检测与真实运行边界；使用代表版本验收，不伪造计算结果 |
| 开发机有数据但干净仓库无法构建 | 白名单打包、锁定依赖、跟踪测试和窄范围文档例外、干净 checkout 验证 |
