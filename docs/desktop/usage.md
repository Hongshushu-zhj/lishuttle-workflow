# LiShuttle Workflow 桌面版使用说明

版本：0.1.4，Windows 10/11 x64。应用携带 Python 运行环境，安装后无需另装 Python、Node.js 或启动 Web 服务。LiShuttle 引擎、第三方库及地图/工参/模型等业务数据由用户提供，不随安装包分发。

## 安装与数据位置

运行 `LiShuttle-Workflow-Setup-0.1.4-x64.exe`，选择当前用户可写的安装目录。应用为当前用户安装，支持自选目录。安装资源与用户配置分离，更新或卸载默认保留用户数据。

- 正式版：`%LOCALAPPDATA%\LiShuttleWorkflow`。
- 开发版：`%LOCALAPPDATA%\LiShuttleWorkflow-Dev`。
- “环境与路径”可查看内置 Python 的路径、版本和可用状态，并打开实际数据位置；运行记录、快照、日志和维护归档都保存在这里。
- 安装目录不用于保存个人项目路径、运行输出或配置。引擎编译与计算仍写入你选择的外部项目、构建和结果目录。

本次构建尚未配置发布者签名；公开分发前应完成代码签名和干净 Windows 电脑验收。

## 首次配置

1. 在“项目与环境”粘贴引擎源码根目录，或用目录按钮选择，再点击“校验并添加”。根目录应包含 CMakeLists.txt 与 LiShuttle 源码。
2. 不确定资源在哪里时，在“发现本机资源”选择搜索范围并开始发现。扫描按目录内容识别引擎、地图、工参任务、配置与动态库，支持取消，默认有限制；它不会执行发现的程序。
3. 候选结果仅填入草稿。核对后显式添加项目或保存配置；多个候选由你选择，不会默认认定第一个就是正确来源。
4. 指定地图根目录、工参任务根目录和输出位置。基础配置来源默认识别当前项目的 `ThirdPart/Config`（或 `Config`），动态库可填写 `ThirdPart/Dll`。选中的项目内配置源和 DLL 根目录按相对路径保存；也可指定外部目录。
5. “程序准备”选择实际构建预设。已有可用程序时应用已有程序；需要编译时，再配置 Visual Studio、CMake、Ninja 与 MSVC 环境脚本并执行体检/编译。

动态库根目录下应包含 `Debug`、`Release` 子目录；构建预设决定实际使用哪一个，`RelWithDebInfo` 和 `MinSizeRel` 使用 `Release`。切换预设立即预览实际来源，应用已有程序或编译时固定生效。旧版直接选择 `Dll/Debug`、`Dll/Release` 的配置会转换为其父目录；特殊的旧版自定义来源继续保留，之后可重新选择根目录。

“程序准备”可比较所选源与实际 Bin 的 DLL。先点击“比较当前 DLL”，需要替换时点击“准备 DLL（备份并替换）”，仅复制 DLL，已有文件先备份，失败回滚；运行 XML、模型、天线及源中没有的文件保持原样。更改根目录或预设本身不会替换已有 DLL。

本机工具链及已保存的共享资源路径全项目共用。项目可用相对路径覆盖共享默认值；构建预设仍按项目保存。旧档案会自动提取共享路径，优先使用原活动项目的值，并保留 `project-profiles.json.shared-paths.bak`。项目切换前处理未保存草稿。

## 三种运行 XML 入口

- **使用已有运行 XML**：直接读取当前构建的 XML，不重新渲染、复制业务资源或修改 VS 启动项。
- **原字节副本导入**：把外部 XML 新增为副本。源文件、根 name、参数和路径保持原样；相对路径按当前程序目录解释。
- **新建与路径适配**：用完整项目样例创建配置，或按任务 XML 生成专用副本。先核对路径变化、实际输出目录、工参同步及天线/模型开关，再确认装配。

文件名和 XML 根 name 可以不同，结果目录按实际根 name 计算。加载或装配后，参数保存、输入变动都会使之前的运行前检查失效。

## 编辑与运行

XML 标量在完成字段编辑后自动保存，失败保留草稿；结构化或重复字段显示为只读。功能参数范围、触发条件与源码依据保留在界面中，未审阅功能需核对全部字段。ThirdPart 默认只恢复项目样例已有值，不自动补写缺失字段。

CSV 必须先加载再编辑，并点击“保存 CSV”才能落盘。编码、表头、内容版本与格式版本一起核对；原文件保留备份。整列修改需要明确选择列并确认。计算半径可能实际来源于工参 CSV，界面会显示实际修改文件。

运行前检查只读核验 XML、CSV、地图、天线、模型及路测依赖。开始运行时后台持锁重新检查；准备、计算、取消、结果验证与归档完成前保持占用。日志、取消和结果固定到会话 SID；查看历史不会改变当前装配。

退出码 0、目录有文件或时间戳变化均不独立表示业务成功。结果区展示进程、产物、业务三层证据及成功/部分成功/无更新/未确认/失败/取消状态。历史当时结论与当前文件是否仍匹配分别展示。

## 关闭、冲突与故障

有未保存编辑或配置草稿时，关闭窗口会提醒。后台有任务时，应用确认后停止自己拥有的进程树，等待结果收尾和归档再退出。不要用系统任务管理器强制结束应用来代替正常取消。

文件冲突时先核对外部改动；保留草稿，或明确放弃并重新加载。写入请求发出但没有收到可靠响应时，会显示“操作结果待核对”，不会自动重发。先刷新状态、核对真实文件和运行记录，再决定下一步。

日志抽屉直接推送任务进程的真实输出，支持尚未换行的进度、断线续读、搜索、跟随、调整高度和完整另存为。完整导出直接写入所选文件，不受界面显示行数或原先 16 MiB 文本保存上限限制。旧运行记录仍可查看和导出。引擎尚未刷新到管道的内部缓存，以及只写文件的日志，不会自动变成终端输出。可在“环境与路径”导出诊断与配置快照；这些文件可能含本机路径，发给他人前先检查内容。

## 导入旧平台与维护

在“环境与路径”选择旧平台根目录，先预览再导入项目档案、任务绑定与空缺工具链字段。可勾选导入已结束会话的日志和归档；不复制原业务结果目录，不改写旧平台。源或目标变化使预览过期，需要重新预览。

现有桌面项目不会被覆盖，导入前创建备份。找不到的旧路径需在本机重新定位。可选填“旧目录前缀”和“新目录前缀”，逐项预览实际配置路径变化与本机存在状态；只处理已知配置和任务绑定的路径字段，不改写源 XML、历史运行上下文或任意文本。修改映射后必须重新预览。运行中和未完成归档的历史会话不会作为完成记录导入。

高级维护只预览并归档可核验的平台历史配置；保留当前配置、手写和来源不明文件。维护归档位于用户数据目录，并包含恢复说明。执行前务必查看范围。

## 从源码构建

构建机需 Node.js/npm；首次准备 Electron、嵌入式 Python 与安装器工具需要网络，或预先填充经校验的缓存。离线安装和离线运行不等于首次源码构建不需要网络。

```powershell
npm ci
npm --prefix desktop-ui ci
npm --prefix desktop-ui run typecheck
npm --prefix desktop-ui run build
npm run desktop:prepare
npm run desktop:dev
npm run desktop:dist
```

`desktop:dist` 输出正式版安装包到 `release/stable/<版本号>`（当前为 `release/stable/0.1.4`）；`desktop:dist:dev` 输出独立开发版到 `release/dev/<版本号>`。不同版本各自保留，避免覆盖正在使用的旧版目录。依赖版本和 Python 校验值固定在锁文件及准备脚本。打包校验采用白名单，排除本机 env、项目、结果、运行历史和业务数据。
