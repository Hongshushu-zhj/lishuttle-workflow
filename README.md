# LiShuttle 本地运行平台

在 Windows 浏览器中选择地图和任务、修改运行参数和工参 CSV、编译并运行 LiShuttle、查看结果和日志。

后端使用 Python 标准库，前端是原生 HTML/CSS/JavaScript，不需要 Node.js、npm 或额外 pip 包。本教程只介绍 Windows 本地运行。

**本仓库不包含 LiShuttle C++ 引擎源码、第三方库、地图和真实任务数据。** 使用者需要单独取得这些资源并配置本机路径，才能完成计算。配置模板中的路径只是示例。

首次 clone 后按以下顺序操作：

1. 安装 Python，取得独立的 LiShuttle 引擎项目、完整 ThirdPart 资源及业务数据（第 1～2 节）。只有需要编译时才安装 Windows C++ 工具链；已有匹配 exe 可直接复用。
2. 双击 `启动平台.bat`：首次打开会自动查找并保存本机工具链，供所有引擎项目复用；添加引擎项目后，在“项目配置”确认其预设与数据路径（第 3 节）。也可先运行自动配置命令，无需手工找工具位置。
3. 执行体检，缺少 exe 时编译（第 4 节）。
4. 启动平台，选择项目、地图、任务和功能，装配、调整参数，再运行并检查结果（第 5～6 节）。网页装配会一并补齐基础运行资源。

换电脑不需要沿用原作者的盘符或 `Lab+日期` 项目名称；但目前支持的是符合约定目录结构的 Windows 本地环境。可配置路径与需要改代码才能适配的限制见第 10 节。

## 1. 准备环境和数据

推荐 Windows 10/11（64 位）和 Python 3.13（当前开发环境版本）。其他 Python 3 版本尚未逐一验证。

| 必需内容 | 检查方式 |
| --- | --- |
| Python 3 | 安装时勾选加入 PATH；终端执行 `python --version` 显示 Python 3 的版本 |
| LiShuttle C++ 项目 | 根目录包含 `CMakeLists.txt`、`LiShuttle/`、`SwanUtility/incl/LiShuttleTypes.h`；编译还需可用的 `CMakePresets.json` |
| 第三方库 | 包含引擎所需的 `ThirdPart/Lib`、Windows DLL 等文件 |
| 运行配置 | `ThirdPart/Config` 内有运行单、场景、天线、模型、日志及签名配置 |
| 业务数据 | 与引擎版本和功能匹配的地图、工参、区域等数据 |
| 编译工具（仅编译需要） | VS2022 或对应 Build Tools，安装“使用 C++ 的桌面开发”、项目需要的 Windows SDK、C++ CMake 工具和 Ninja |

引擎项目、第三方库和业务数据请向项目维护者获取，仓库中的示例任务单不附带实际数据。若已有可运行的 Windows 构建产物，可以跳过编译，但仍需完整的依赖和运行配置。

配置源中必须有完整样例，用于生成运行单和读取默认值：室外为 `CONFIG_SRC/runtimelibrary/runtimeschema.xml`，室内为同目录的 `indoorruntimeschema.xml`。DLL 需要与 exe 的架构、Debug/Release 配置及引擎版本匹配。引擎自己的 CMake 预设、第三方依赖路径也必须适用于本机，平台不会自动修复引擎构建文件。

把工作目录放在自己有写入权限的位置。现有批处理使用 GBK 代码页，首次使用建议采用简单的英文路径，避免 `!`、`%` 等特殊字符。

## 3. 快速配置本机与项目

### 需要编译时：自动搜索工具，一台电脑配置一次

首次 clone 后，准备第 1 节的 Python（需要编译时再安装工具链），再双击 `启动平台.bat`。网页首次加载时会查找本机工具，**将已验证且尚未配置的工具地址直接保存**；以后添加或切换引擎项目都复用，不必再填一遍。

也可以先在仓库根目录运行，无需先登记引擎项目：

```powershell
python .\scripts\project_config.py --setup-machine
python .\scripts\project_config.py --show-machine
```

第一条搜索并保存空缺项，第二条显示当前全局值。工具查找顺序是 VS Installer 的 `vswhere.exe` 注册信息、常见 VS 安装目录文件检查、系统 `PATH` 中的 CMake/Ninja；VS 安装在自定义盘符时，优先通过注册信息定位。只接纳实际存在的目录/程序，优先组合同一套 VS 内的 CMake、Ninja 和 `vcvars64.bat`，不会执行引擎 CMake 文件，也不会自动安装软件或修改系统 PATH。

| 配置范围 | 配置项 | 使用方式 |
| --- | --- | --- |
| 本机全局 | `VS_ROOT`、`CMAKE`、`NINJA`、`VCVARS` | 自动搜索后直接保存；所有引擎项目和本地脚本共用 |
| 每个引擎项目 | 构建模式/预设、`CONFIG_SRC`、`DLL_SRC` | 选择 Debug/Release 后自动派生构建/安装目录、程序名；确认资源后保存 |
| 每个项目的数据 | `MAP_ROOT`、`GONGCAN_ROOT`、`OUT_ROOT`、`DT_ROOT` | 按真实业务数据选择，可显式指向共享目录 |

这里的“全局”指**本机这份平台仓库管理的所有引擎项目**，不是 Windows 系统设置，也不跨其他 clone 自动同步。配置保存在被 Git 忽略的 `env/project-profiles.json` 中：全局工具在顶层 `machine.values`，项目配置在 `profiles.<项目ID>.values`。换电脑请重新 clone 并自动检测，不要复制另一台电脑的本机配置或快照。

“项目与环境”中的“本机工具链（全局）”可查看当前值和下拉候选。点击“自动检测并保存本机工具链”会重新搜索并补齐空缺；已经保存的自定义值保持不变。需要改用另一套工具时，选择候选或切换“手动填写”，然后点击“保存本机工具链”，立即对所有项目生效。改变全局配置会让旧页面修订失效，其他已打开页面需要刷新；已经启动的命令继续使用启动时的配置快照。

**没有找到工具时：** 检查 Python 是否已加入 PATH；VS Installer 中确认安装了 C++ 桌面开发、MSVC x64/x86、Windows SDK、C++ CMake 工具。若某项仍为空，安装后重新检测，或指定真实文件位置：

```powershell
# 示例路径必须替换为本机实际安装位置；路径含空格时保留整段引号。
python .\scripts\project_config.py --set-machine "VS_ROOT=C:/Program Files/Microsoft Visual Studio/2022/Community" --set-machine "CMAKE=C:/Program Files/Microsoft Visual Studio/2022/Community/Common7/IDE/CommonExtensions/Microsoft/CMake/CMake/bin/cmake.exe" --set-machine "NINJA=C:/Program Files/Microsoft Visual Studio/2022/Community/Common7/IDE/CommonExtensions/Microsoft/CMake/Ninja/ninja.exe" --set-machine "VCVARS=C:/Program Files/Microsoft Visual Studio/2022/Community/VC/Auxiliary/Build/vcvars64.bat"
```

手动保存只做配置文本校验，请用 `Test-Path` 或“体检”确认文件存在。VS 卸载/迁移或误拷贝了旧电脑配置时，可在网页改正；也可以先清空旧工具地址，再自动查找，避免“已有值保留”阻止更新：

```powershell
python .\scripts\project_config.py --set-machine "VS_ROOT=" --set-machine "CMAKE=" --set-machine "NINJA=" --set-machine "VCVARS=" --setup-machine
```

工具配置正确后添加引擎项目。自动检测无法提供尚未取得的地图、任务包、ThirdPart 或源码，业务资源仍需自行准备。

### 本地项目档案与切换

网页、渲染器和本地 Windows 脚本共同读取 `env/project-profiles.json`，运行时合并本机全局工具链和所选项目配置。每个项目独立保存构建预设、构建/安装目录、exe 名、配置/DLL 源目录及地图、工参、路测、输出根目录；切换 A→B→A 会恢复各自项目配置，并复用同一份本机工具链。没有旧 env 时也可以在网页添加首个项目。

打开或切换项目时，网页会自动检测并填充尚未配置的项目字段：读取本项目的 `CMakePresets.json` / `CMakeUserPresets.json`（含继承和 include），优先选用已有可执行文件的 Windows x64 Ninja 预设；从项目内容识别程序名、配置源和 DLL 目录。地图、工参、输出和路测目录只列出实际存在的约定目录，包括明确标注的同级共享候选；多个业务目录需下拉选择，未找到则说明原因并允许手动填写，不会编造路径。

“项目配置”直接显示检测值和每项来源，候选可下拉选择或切换手动填写。通过上方 Debug/Release 和项目预设选择构建配置，自动派生构建/安装目录、程序名和匹配的 DLL 目录，不再手填这些构建字段。自定义 DLL 目录仍保留。已保存的项目配置和本次手动输入不会被重新检测覆盖，也不会继承其他项目档案。**项目检测结果是草稿，点击“保存当前项目配置”后生效；本机工具链自动检测则直接保存。**

升级已有配置时：旧 `env/local-win.env` 首次导入前备份为 `local-win.env.profiles.bak`；旧版项目工具链首次升级前备份整个档案为 `project-profiles.json.machine.bak`。迁移使用当前活动项目的工具配置作为全局起点，不拼接其他项目的工具值，其余项目原来的工具值可从备份查看。旧 env、原有备份及任务数据保持不变。**导入后请用网页或上述命令修改；继续编辑旧 env 不会覆盖档案。** 本机配置、备份及快照不提交 Git。配置源与 DLL 源可以是相对项目路径，也可以是本机绝对路径；构建/安装目录沿用相对项目的目录约定。

仅在需要兼容旧入口时，才从 `env/local-win.env.example` 复制 `env/local-win.env` 作为首次导入来源；新安装推荐自动配置，无需复制模板。首次导入前若 env 已存在，不要重新复制覆盖；文件使用 UTF-8、`KEY="VALUE"` 和正斜杠路径。

一次网页请求固定配置；渲染和工具子进程使用 `env/snapshots/` 中按内容摘要保存的快照。本地 `doctor/build/stage/run` 入口通过 `scripts/load_local_env.bat` 在开始时固定快照，后续网页切项目不会改变已启动命令的配置。旧页面修订号不符会被拒绝，需刷新。独立的 `server` target 未纳入此次适配。

直接使用 Python 时可明确选择已登记项目，不改变网页当前选择：

```powershell
python scripts/render_schema.py --print-env local-win --project "D:/LiShuttle/项目A"
python scripts/render_schema.py jobs/<项目ID>/web-demo.env local-win --project "D:/LiShuttle/项目A"
```

网页生成的任务单带项目标识，不能在另一个项目下直接复跑。本地批处理会明确拒绝包含 `!` 的配置/路径，避免 Windows 延迟展开吞字符；该情况下请调整路径，或使用 Python 渲染入口并直接启动引擎。中文和空格路径有独立的 Windows 批处理回归覆盖。

### 配置项对照

| 配置项 | 含义 |
| --- | --- |
| `PROJECT_DIR` | 引擎项目的绝对路径，不是平台目录；该目录及其父目录必须存在 |
| `PRESET` | 真实的 Windows CMake 预设名，示例为 `x64-release` |
| `BUILD_SUBDIR` | 自动取所选预设的 `binaryDir`，相对于引擎项目；首次编译由 CMake 创建，网页无需填写 |
| `INSTALL_SUBDIR` | 自动读取预设的安装目录；可选，默认从构建树运行，不需要安装 |
| `EXE_NAME` | 内部运行元数据，自动读取 CMake 主程序目标或 `Bin/` 下的真实产物，网页无需填写 |
| `VS_ROOT` | 本机全局：VS2022/Build Tools 实际安装根目录 |
| `CMAKE`、`NINJA`、`VCVARS` | 本机全局：工具文件的绝对路径，不是文件夹路径 |
| `CONFIG_SRC` | 相对项目目录的配置源，通常为 `ThirdPart/Config` |
| `DLL_SRC` | 相对项目目录的 DLL 源，通常为 `ThirdPart/Dll/Release`；需匹配构建配置 |
| `MAP_ROOT` | 地图根目录，每个子文件夹是一座城市或室内场景 |
| `GONGCAN_ROOT` | 本地工参任务根目录，每个子文件夹是一份任务包；CLI 任务引用包内的具体输入文件 |
| `OUT_ROOT` | 可写的结果根目录，通常按任务名存放计算产物 |
| `DT_ROOT` | 可选：仅路测、校正等相关功能需要的数据目录 |

平台不自动登记父目录中的其他引擎项目。在项目入口点击“添加项目”，输入项目根目录，通过验证后加入本机列表并切换。目录名称不限，以 `CMakeLists.txt`、`LiShuttle/`、`SwanUtility/incl/LiShuttleTypes.h` 组合识别；缺少构建预设或完整运行样例时给出提示。本机列表保存于 `env/projects.json`（不提交 Git），升级前已配置的当前项目会保留。切换时刷新功能、地图和任务列表，并清空旧项目的参数与运行状态；工具链复用本机全局配置，预设与数据根恢复对应项目配置。

配置后创建缺失的输出和工作目录，例如 `OUT_ROOT`。不要用空文件夹替代真实地图或依赖。

### 新项目按顺序操作

网页采用六个有序、可折叠阶段，阶段导航显示当前状态和需要处理的原因，可随时返回编辑：

1. **项目与环境**：在该阶段内添加或切换本地引擎项目，项目选择器、完整项目目录、预设和输出根目录集中展示，收起后仍显示项目名称。确认资源与数据根目录并保存项目配置。检测值和手动修改都是草稿，保存后才生效；全局工具链仅在需要编译时配置。
2. **程序准备**：同卡选择 Debug / Release、实际预设并核对 Bin/exe 路径。已有匹配 exe 时使用现有程序，不要求编译器、CMake 或 Ninja 齐全；仍须具备匹配 DLL 和运行配置。更换构建选择后明确保存/应用，不能把未应用草稿当作运行目标。需要编译时点击“编译所选配置”，也可在此执行体检。保存源码修改后，该按钮执行 CMake 配置及增量构建，编译和链接受影响的目标；不执行强制全量重新生成。是否与 Visual Studio 的构建一致，取决于是否选用相同的项目、预设、工具链和目标。检测到 exe 只证明文件存在，本次编译是否成功应查看操作日志；编译后需重新装配和运行前检查。
3. **任务与输入**：集中选择功能、地图、任务包、工参 CSV、已有 XML 或模板分支，确认任务名/ID、区域及本地路径。工参编辑器始终指向同一已选 CSV。
4. **装配与确认**：核对目标 Bin、XML、实际输出目录与复制策略。已有 XML 先“预览路径修改”再“确认装配此配置”；模板分支核对装配摘要后生成，摘要不是已有 XML 的逐项差异预览。
5. **参数与运行前检查**：修改当前目标 XML 或 CSV 并保存，再执行运行前检查。保存成功与检查通过分别显示；检查过期时重新检查。后端在正式启动取得占用后仍会复查。
6. **运行与结果**：核对固定运行摘要后启动，查看日志、取消和本次结果。共用操作日志面板也显示体检、编译和装配输出，不必离开当前阶段。

每个阶段标题右侧显示带箭头的“展开 / 收起”控件，也可点击整行标题，或聚焦标题后按 Enter / 空格操作。收放只改变显示，不清空选择或更改运行就绪状态。

更换功能、地图、任务、CSV、源 XML、区域、路径、复制策略、任务身份或已应用的构建资源后，旧预览、装配和检查会过期，需重新装配；不能在新选择下启动旧任务。保存目标 XML 或 CSV 内容只使检查过期，保留当前目标文件，不自动重新装配。搜索、筛选、展开和导航不使配置过期。重新装配可能覆盖手工参数，应先核对覆盖提示和备份。

CSV 表格的未保存编辑与磁盘文件不同。更换 CSV/项目或继续装配、检查、运行前，先明确“保存”或“放弃未保存编辑”；不要以为屏幕上的新值已经写入文件。放弃仅撤销未保存内容，不回滚此前保存。XML 参数修改后直接保存；保存失败会保留编辑值，并显示“重试保存未完成的修改”和“放弃未保存的参数修改”。未完成的编辑处理前，不会切换输入或启动运行。保存内容只使运行前检查过期，不隐式重新装配。

参数和 CSV 保存会检查读取时的文件内容版本。另一个页面、VS 或 Excel 已修改文件时，本页保存被拒绝并保留草稿；重试不会强制覆盖。先复制需要保留的草稿，再使用明确的放弃/重新加载按钮取得磁盘上的新内容。计算半径还检查 XML 指向及 CSV 的版本，避免把旧草稿写入后来切换的工参。

构建路径会在编译前显示为“尚未生成”，只有目录实际存在才显示“已生成”；程序名来自 CMake 目标和构建产物，编译结束后重新识别。目录存在不代表编译成功，请检查共用操作日志中的退出码及日志。Debug 与 Release 分别使用各自预设目录和匹配 DLL，不会清空已有构建目录。切换配置后旧运行单失效，需要重新装配。项目要求在 `<binaryDir>/Bin/` 输出主程序；无法明确识别主程序时，检查 CMake 的 add_executable / OUTPUT_NAME 或产物布局。

## 5. 准备地图和任务

室外地图通常需要以下结构，索引引用的数据文件也必须齐全：

```text
MAP_ROOT/
└─ city-name/
   ├─ heights/index.txt
   ├─ heights/projection.txt
   ├─ clutter/index.txt
   ├─ clutter/menu.txt
   ├─ buildings/index.txt
   ├─ buildvector/index.txt
   └─ city-namecluttermatchsettings.xml
```

杂波匹配配置也可使用项目默认文件。室内地图按 `MAP_ROOT/scene-name/` 组织，场景目录当前层只要有 `.das` 文件，就识别为室内地图，不限制文件名长度，扩展名不区分大小写；同目录同时存在室外索引时也优先判为室内。支持一个或多个楼层文件，如 `building.das`、`test-indoor.das`、`a.das`、`FLOOR.DAS`。地图扫描、项目配置候选和装配检查共用这一规则，XML 的 `MapPath` 填场景目录。

室内类型识别与引擎兼容性分开：当前引擎仍会跳过大写扩展名或不足 6 字节的文件名，因此运行预检会明确指出这些已识别地图的名称不兼容，避免只运行部分楼层；可改用 `floor1.das` 等兼容名称。预检仍检查地图内容、重复楼层、AP 楼层匹配，以及当前引擎会额外读取的非 `.das` 条目。平台不自动改名或改写地图。

升级后需重启平台并刷新页面，再重新扫描地图。地图根目录应保持为各场景的父目录，选择识别出的室内场景后自动切换到室内预测。

建议 Web 任务按以下结构组织：

```text
GONGCAN_ROOT/
└─ task-name/
   ├─ task-name.csv       # 工参
   ├─ task-name.txt       # 室外区域；室内可不提供
   ├─ antennas/          # 按任务需要提供
   ├─ models/            # 按任务需要提供
   └─ scenesettings.xml  # 按任务需要提供
```

平台读取 CSV 前两行，按小区/AP 标识、位置、天线和功率等字段组合识别工参，排除路测及结果汇总 CSV。任务包 XML 的 `EngineeringFilePath` 可辅助定位：旧机器路径只作线索，在当前任务包匹配本机文件并校验表头。唯一候选自动选中；多个候选无法唯一确定时，须在“任务与输入”的“工参文件”下拉框选择；没有有效候选时停止装配。页面显示识别依据和实际路径，“任务与输入”中的工参编辑器同步使用选定文件。装配前后端重新扫描校验，文件被移动或表头变化后需重新选择。

区域文件与选定的工参 CSV 同名会优先匹配。室外区域通常每行一个 `经度,纬度` 顶点，首尾点重复，具体格式和坐标系以引擎要求为准。

工参字段必须匹配引擎版本和功能，室内 AP 工参与室外工参不能混用。没有完整业务数据，可以检查网页和配置，但无法验证计算。

双击 **启动平台.bat**，或执行：

```powershell

```

1. 按上述六阶段导航操作。在“项目与环境”登记并保存项目，在“程序准备”应用匹配的已有程序或按需编译；工具链缺项只阻断实际需要它的动作。
2. “任务与输入”默认显示“使用当前构建已有配置”，选择 `Bin/runtimelibrary` 中的 XML，点击“使用此配置”即可继续编辑、检查和运行，无需重新选择地图或任务包。有上次选择时自动恢复；外部 XML 可先预览，再导入副本。首次制作配置时，切换到“从样例新建／从任务包适配”，扫描并选择地图和工参任务。目录修改及工参与地图绑定只在当前项目生效。

4. 新建或任务包适配时，点击“装配并渲染”，自动先从当前项目 `CONFIG_SRC`、`DLL_SRC` 补齐 Bin 的基础资源（含目录结构和 exe 旁的 `config/*.xml`），然后生成任务配置，最后按勾选装配任务天线、模型。基础补齐只复制缺失文件，保留已有运行 XML、模型、天线和 DLL；跳过源中的 `.bak`、`.task-bak`、`.tmp` 备份。源目录缺失时停止并显示错误；装配输出展示复制来源、目标和数量。任务包配置预览阶段不复制，确认后才装配。直接加载当前构建已有 XML 跳过本步，不复制资源、不渲染、不写 VS 启动项。专用运行单生成在 exe 的 `runtimelibrary/` 下，任务单按项目生成在 `jobs/<项目ID>/<构建标识>/web-*.env`。室外任务以当前项目 `CONFIG_SRC/runtimelibrary/runtimeschema.xml` 为完整底稿；室内 `predindoor / plindoor / indoorrays` 使用独立的 `indoorruntimeschema.xml`，要求底稿声明 `MapFormat=indoor`。保留参数、注释、顺序及样例默认值，仅替换任务名、数据路径和任务单明确指定的算高/层高；室内底稿重复接收高度的处理见下文。样例缺失或无效时直接报错，不回退到通用样例或精简模板。参数面板出现不表示输入数据已经齐全。
5. 检查并保存参数。`cali / pred / predindoor / acp / commsensing` 默认进入“本功能可配置 + 未分类”，按本地引擎源码调用链显示功能参数及路损、地图、工参、天线依赖。“本功能当前生效参数”进一步隐藏开关未启用的条件项、仅启动读取项和未分类字段；“全部已识别参数”保留当前运行 XML 的所有实际字段。切换功能会重新计算范围，手选的显示范围和搜索词保持不变。参数旁显示触发条件及源码依据；缺失的强制读取元素和可选参数单独提示，不冒充已配置值，也不自动写入 XML。其他功能暂沿用旧字典推荐范围。
   每个可编辑参数旁提供“ThirdPart 默认”按钮：按实际运行 XML 的 `MapFormat` 选择当前项目的室内或室外完整样例，数值从该样例读取；路径只填入当前项目配置源内确实存在的对应资源（例如场景配置、杂波匹配配置），点击即备份并写入目标 XML，不修改任务源 XML。无可靠默认资源、样例缺少字段、样例字段重复/结构化或目标 XML 缺少字段时禁用并提示；留空不会自动覆盖。需要调整 CSV 时，在“任务与输入”的工参编辑器加载、编辑并明确保存或放弃。
6. 在“参数与运行前检查”执行检查，处理缺项并取得当前有效的通过报告后，在“运行与结果”点击“运行 lishuttle”（启动时会在取得占用后重新检查）。报告定位具体参数和文件，不自动修复输入。“导出运行日志”保存当前会话的全部控制台输出（含指令、导出时间、状态和退出码）为 UTF-8 `.log` 文件，运行中也可导出。体检、编译输出同样支持导出；不包含引擎另行写入的历史 `uplan.log`。刷新页面会恢复本服务仍在执行的会话；服务重启后可从“最近运行”查看日志、当时结论和归档。日志连接中断会显示状态并从已读取位置重试。
7. 完成后在“运行与结果”分别检查进程退出码、产物验证、业务可用性。“结果”默认查询当前会话；勾选“仅浏览任务目录”或输入其他任务名则只查看历史文件，明确标注“未关联本次运行”。
8. 需要整理时，在“装配与确认”的高级维护区域展开“清理平台历史配置”，先“预览可清理配置”，核对后“归档并清理以上配置”。仅处理当前项目所选构建目录中具有可核验平台渲染记录的历史 XML、`.bak`、manifest、生成任务 env 及对应平台 VS 启动项；优先保留页面当前运行单，页面无选择时保留当前构建记忆的配置，再后备保留最近生成的一份。任务源 XML、被其他 XML 或手写启动项引用的配置、基础样例和结果均保留。新任务 env 按项目和构建分别存放；旧版共享 env 无法确认构建独占时保留。来源不明的文件跳过；平台进程运行时拒绝清理，文件变化后须重新预览。文件移至本工作流已忽略的 `docs/runtime-config-archives/<时间及唯一编号>/`，不会永久删除；按 `restore.json` 将文件复制回 `source` 路径即可恢复，需要恢复启动项时参考同目录 `launch.vs.json.before` 合并，避免覆盖后来新增的启动项。清理完成刷新候选，此入口不清理其他 Debug/Release 构建目录，需切换对应配置再预览。

室外路损选 `pl`，室内路损选 `plindoor`，室外预测选 `pred`，室内预测选 `predindoor`（需要引擎支持）。任务 ID 通常保持默认 `1`；预测产物位于实际任务输出目录的 `pred/<任务ID>/`。最大计算高度、层高在装配后的配置参数面板调整；网页生成任务单不额外覆盖这些值。

室内预测装配后，参数区显示当前 XML 实际定义的 `MaxDeepth`（室内射线树最大深度，保留引擎原拼写）、`MaxReflection`、`MaxDiffraction`、`MaxPenetration`、`MaxRayNumber` 及室内接收缩放参数。这些参数直接保存到 XML，无需重编译；调整深度等射线参数后应确认 `IsForcedCalc=true`，避免复用未包含新参数的旧 `.ils` 缓存。此前从通用样例生成的室内任务，请先记录手动调整的值，取消“使用任务已有运行配置”，重新装配并核对参数；复用已有 XML 会保留原有配置，不会自动补写缺失参数。

当前引擎的室内样例包含两项 `DefaultUEHeight`（1、1.5），引擎实际读取首项。仅在新建室内样例任务时，平台保留首项并移除其余简单标量同名项，以消除预检歧义并允许编辑接收高度；装配日志和 manifest 的 `sample_adjustments` 记录原值及保留值。项目样例、任务源 XML 不变，已有 XML 复用、结构化字段及其他重复字段仍保留并提示核对；来源样例重复字段的“ThirdPart 默认”禁用。室内未选择的区域、路测目录清空，避免沿用样例作者机器的路径。

平台一次只执行一个运行、体检、编译或装配任务，从准备输入到进程树退出、结果验证及归档结束均保留占用。期间拒绝再次启动，以及装配、参数/CSV 修改、配置保存、项目切换和相关清理；后端返回 HTTP 409 和 `RUNTIME_BUSY`，其他浏览器标签页也适用。日志、结果和停止仍可用；停止会终止本服务托管的整个子进程树，确认结束并保存记录后释放占用。多个平台服务及 `run_local.bat` 共用 Windows 系统临时目录下的资源锁；相同 Bin 或输出目录不能同时使用，进程被强制结束后锁由操作系统释放。页面会提示其他实例占用，但不能取消另一个实例的任务。手动 exe、VS、Excel 和其他不使用该协议的程序不受它管理。

### 最近运行与归档

“运行与结果”的“最近运行”按当前项目分页，选择记录可读取原会话日志、结论并打开本次归档，不会改变已装配任务。结果同时显示“当时验证结果”和“当前文件匹配状态”：当时成功并不保证原目录未被后续运行覆盖；当前文件变化、缺失或无法确认时，不显示当前可用的绿色成功状态。只浏览任务目录仍不作为任何会话成功的证据。

本地记录位于本工作流的 `.lishuttle-runs/<会话号>/`，已加入 Git 忽略。`session.json` 保存时间、进程退出码、结论和归档索引，`context.json`、`command.json`、`baseline.json` 保存当时项目配置、启动参数和验证基线，`inputs/` 保存启动 XML 及存在的 manifest，`console.log` 是本次独立控制台日志。必需输入快照无法保存时不启动引擎。`artifacts/` 仅复制结果验证明确列出的产物和运行期间新增或变化的 `uplan.log`，核对验证时的 SHA256；不搬走原文件，不归档整套地图或射线缓存。原路径与归档路径可在 `session.json` 的 `archive.files` 中对应。

共享 `uplan.log` 可能含更早运行的内容，只能表明运行期间新增或变化，不等同于纯本次日志。没有验证摘要的文件，其归档摘要不能替代“当时已验证”证据。归档失败、摘要不符、文件缺失会明确显示归档不完整，保留当时验证结论；原文件当前状态另外核对。服务意外退出且原进程已结束时，未完成会话显示“已中断／未确认”，不能恢复执行。历史不会自动删除；需释放空间时，等待相关运行结束，先复制需要保留的整个会话目录，再手工清理。不同工作流目录各自保存历史，同一工作流启动的 CLI 与网页可查看相同记录。

本地入口与网页复用相同预检、进程树托管、结果判断和历史归档。`--no-render` 或任务单 `RENDER_BEFORE_RUN=0` 只跳过生成，不跳过预检；生成失败会回滚并退出，同名旧 XML 不会被继续执行。每份任务单目前要求一个 XML，多份 XML 请分为多个任务单逐个运行。Ctrl+C 会停止进程树并等待收尾和归档，避免留下后台引擎。

退出码不再固定为 0：引擎返回非零时原样返回；配置或预检失败返回 `2`；引擎返回 0 但业务未验证成功返回 `3`；取消返回 `130`；只有进程成功且结果验证成功才返回 `0`。完整结果仍以会话结论、日志和归档状态为准。

首批完整预检查与结果契约覆盖 `pred`、`commsensing`、`predindoor`、`cali`。两项室外预测按 `ground`（基础层）、`floor/building`（实际建筑楼层）、`3d`（配置高度切片）检查；floor 缺少可用的所选建筑数据、又无法确认可兼容缓存时阻止启动。3d 的配置层数为 `floor(MaxCalcHeight/DefaultFloorHeight)+1`，包含基础层。室内预测按 DAS/AP 实际楼层检查；cali 按地面实测射线和校正产物检查，不要求室外三维预测文件。其他功能仍受公共互斥保护，尚无完整产物契约时显示“未确认”。

“装配任务天线”和“装配任务模型”分别控制资源复制。天线目录同时支持 `antenna/`、`antennas/`，其中 XML、方向图及子目录文件复制到当前项目的 `Bin/antennas/`，覆盖前备份为 `.bak`（任务包内的 `.bak` 文件不复制）。仅在所选任务识别到天线 XML 或非空的天线资源目录时显示“装配任务天线”选项；未识别到资源时隐藏、取消勾选，后端也跳过天线装配。不勾选时不复制、恢复或移除项目现有天线文件；仅有方向图目录而没有天线 XML 时，勾选后沿用恢复项目默认天线 XML 的规则。再次渲染会按项目样例和任务单重新生成，覆盖手改的运行单。渲染输出及 `.manifest.json` 的 `schema_source` 记录本次使用的底稿路径。CLI 显式指定其他名称的 `TEMPLATE` 时，仍按自定义模板渲染。

工参编辑、整列修改、计算半径与预检共用 `Bin/cellformat.xml` 的表头行数和列位。明确配置的室外 0/1/2 行表头均保留全部小区；室内遵循引擎固定两行表头。缺少格式文件时，仅确认的中英文表头可编辑；未知、损坏、重复或与配置矛盾的布局只读，超过两行表头暂不支持编辑。预检仍按引擎布局核对，不能因为编辑器能显示单表头就认为默认两行配置可直接运行。零表头工参不会自动出现在任务候选中；已有运行 XML 明确引用该 CSV 且配置正确时，才可按显式格式检查。上述保存草稿只保留在当前页面，刷新或关闭页面前请先另存需要保留的内容。

### 在 Visual Studio 中运行和调试

网页成功完成“装配并渲染”（或确认复用已有 XML）后，会自动在**当前引擎项目**生成或合并 `.vs/launch.vs.json`。Visual Studio 使用这个文件；VS Code 的 `.vscode/launch.json` 是另一种格式，本功能不生成后者。预览阶段和渲染失败时不会写启动配置。

室外任务生成当前引擎头文件中支持的主要功能：`pl`、`pred`、`rays`、`dt`、`cali`、`acp`、`ai`、`scene`；室内任务生成 `plindoor`、`predindoor`、`indoorrays`。本次明确选择的功能也会生成。条目名称为 `[LiShuttle 平台] <任务名>.xml / <功能>`，各条目使用本次任务 XML 和任务 ID，不会误用通用的 `runtimeschema.xml`。

### 从任务包适配运行配置

选择任务后，平台按根节点 `RuntimeSchema` 识别 UTF-8 运行配置 XML，文件名不限于 `runtimeschema.xml`。勾选“使用任务已有运行配置”，选择 XML（一份时预选，多份时手动选择），再选择区域文件；“不使用区域”会把 `PolygonFilePath` 设为空。室内外类型须与所选地图匹配。

有效预览在后台 busy→idle 后仍可确认，提交期间防止重复点击。普通装配错误或目标 XML 未成功生成时，仍有效的预览保留，可按提示手动重试；`RUNTIME_BUSY` 需等待占用结束。输入/项目改变或 `PREVIEW_STALE` 表示原预览失效，必须重新预览。网络中断可能意味着写入结果未知，显示“结果待核对”：先核对目标和状态，再重新预览、由用户确认；平台不会自动重复写入。不要把失败、过期和结果未知视作相同的重试条件。


此模式按所选地图替换常规地图路径、区域路径和 `PathlossDirectory`；网页生成副本的 `RuntimeSchema name` 同步为任务设置中的任务名；计算参数、注释、顺序和换行保留，任务源 XML 不变。工参路径默认保留，勾选“将 XML 工参路径改为上方所选 CSV”才替换 `EngineeringFilePath`。展开“修改本地资源路径”会自动显示当前项目、地图及任务解析出的场景、输出根、地图索引、杂波和路测路径，同时保留原值供核对；更换地图、工参或 XML 后重新识别。任务自带 `scenesettings.xml` 优先，否则使用项目运行目录的场景配置。自动值不会作为手填覆盖保存；手动修改项进入预览及生成任务单。区域文件仅在上方选择，不再提供重复覆盖入口。旧自定义地图索引仅在所选地图内存在同名专用文件时自动定位，否则要求明确填写，不静默换成普通索引。模型复制操作在此模式下停用；天线装配由独立复选框控制。缺少必需字段时直接提示，不补字段或回退到项目样例。

“保存当前工参与地图对应关系”按项目、任务目录、工参和源 XML 保存地图选择、本地路径、区域和工参同步选项，不修改原 XML。保存关系不代表所有文件已就绪；渲染仍重新校验路径。一个父目录包含多份独立运行配置包时，平台分别列出子任务，避免混选资源。本轮只做本机项目和本地路径配置，不解析服务器挂载关系或自动转换服务器任务。

| `cali` | 本次路测处理/校正报告，以及实际更新分支对应的模型；分别展示站点、通用、场景模型的保存情况与统计，区分成功、部分成功、无模型更新和失败 |

预检查只读验证已核实的输入格式与资源引用；动态 DLL、授权及日志初始化仍由实际启动确认。floor 的实际参与楼层或缓存兼容性缺少可靠证据时保留“未确认”，不能把目录标签直接当作建筑物的物理层高。

每次启动固定会话 ID（sid）及当时的项目、构建、功能、任务、XML 和输出目录。后续导航或草稿选择不改变该会话日志与结果归属；查看历史目录也不会将历史文件认作本次产物。输出目录可跨次运行复用，是否属于本次仍由会话基线和产物验证判定，不由目录名或存在文件判定。

平台接口新增 `GET /api/runtime_state`、只读的 `POST /api/preflight` 和 `GET /api/results?sid=<会话ID>`；原启动、输出、取消及任务目录查询字段保留。会话输出补充固定的运行上下文和分级报告。后端使用 Python 标准库；Windows 使用任务对象托管进程树，避免父进程退出后子进程仍写入而提前解锁。

先停止或等待计算结束，再在服务终端按 `Ctrl+C` 退出。也可双击“停止平台.bat”，它按默认端口结束进程及子进程。关闭网页不能停止计算。

## 8. 常见问题

| 现象 | 解决方法 |
| --- | --- |
| 找不到 Python 或跳到应用商店 | 安装 Python 3 并加入 PATH，必要时关闭 Windows Python 应用执行别名，重新打开终端 |
| 缺少 `local-win.env` | 新安装无需此文件；按第 3 节自动配置工具并在网页添加项目，旧 env 仅作首次导入来源 |
| 网页打开但列表加载失败 | 检查配置、项目和父目录是否存在，查看服务终端报错 |
| 地图/任务为空 | 检查两个根目录及第 5 节结构，准备数据并重新扫描 |
| 找不到编译工具 | 补装 VS C++ 组件，填写真实的 CMake、Ninja、vcvars 文件路径 |
| 预设或 exe 找不到 | 对照实际预设和产物核对 `PRESET`、`BUILD_SUBDIR`、`EXE_NAME` |
| DLL 缺失或程序立即退出 | 检查依赖架构与构建配置，重新装配；按引擎要求安装匹配的 MSVC 运行库 |
| 配置、天线、模型、签名文件缺失 | 获取完整 `ThirdPart/Config` 并装配，确认任务资源匹配引擎 |
| CSV 解析失败 | 核对功能、引擎版本、字段、编码和必填值 |
| 完成却无结果 | 检查结果页日志和 exe 旁的 `uplan.log`，先处理首条实际错误 |
| 端口被占用 | 检查已有平台，或执行 `python platform/backend/server.py --port 9000`，访问对应端口；用终端 `Ctrl+C` 退出，默认停止脚本仍查找 8641 |

可以把报错、配置和目录结构交给 AI。优先要求核对文件是否存在、预设是否匹配、第一条日志错误；不要直接清空构建目录或修改原始数据。

### 外部引擎与远程运行边界

LiShuttle 引擎不在本仓库中，其 `CMakeLists.txt`、预设及 ThirdPart 依赖需要另行检查。例如所检查的外部引擎 Linux 构建配置包含固定的 `/home/lishuttle-thirdpart/Lib`、`/home/lishuttle-preinstall`，以及 `/usr/local`、`/usr/lib64` 等约定；这些不是平台环境变量能统一替换的路径。请核对实际取得的引擎版本，必要时修改引擎构建配置。

仓库保留远程运行脚本，但没有提供可直接使用的 `env/server.env` 或对应示例；SSH 主机、账号、密钥、远程项目及数据目录均需单独配置。它们不代表当前 Windows 网页已经支持 Linux 后端部署。
